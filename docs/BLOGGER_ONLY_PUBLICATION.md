# Blogger 단독 발행 운영 계약

## 1. 운영 방향과 원본

2026-11-13 승인된 목표는 Blogger를 유일한 독자용 공개·미리보기 채널로 운영하는 것입니다. GitHub 저장소는 코드·편집 규칙·검토된 운영 문서를 버전 관리하는 데 유지합니다. GitHub Pages production/Preview는 발행 선행 조건이나 이미지 호스트로 사용하지 않습니다. 전환의 실제 배포·사이트 중단·운영 검증 결과는 별도 종료 기록으로 확인합니다. 계약 문서가 있다고 운영 적용 완료를 뜻하지 않습니다.

편집 원본은 `/root/oneplate-ai.github.io/drafts/`, 실행 코드는 `/root/workspaces/oneplate-ai.github.io/scripts/`입니다. 두 위치를 혼동해 초안·승인 파일을 공개 Git에 넣지 않습니다. 승인 기록은 편집 원본의 `.publishing-approvals/`에 보관하며 원고 파일명·제목·날짜·언어·translation_key·SHA-256·예약 시각·이미지 맵을 정확히 결속합니다. 과거 permalink는 원고 식별 메타데이터로 보존할 수 있으나 Pages URL 확인/생성·배포의 근거로 사용하지 않습니다.

## 2. 일정과 한 회차의 흐름

모든 시각은 KST입니다. 일간과 주간은 서로 다른 승인 단위이며, 한 회차는 한국어·영어를 함께 관리합니다.

| 시리즈 | 자료 조사·초안·미리보기/검토 요청 | 승인본 공개 |
|---|---|---|
| 오늘 AI 한입 | 월·수·금 12:00 | 같은 날 19:00 |
| 주간 AI 한 접시 | 금요일 19:30 | 토요일 19:00 |
| 쉽게 먹는 AI | 회차별 정한 일정 | 해당 회차의 승인된 시각 |

일간 수집 기간과 출처/편집 규칙은 [발행 규칙](../PUBLISHING_RULES.md)을 따릅니다. 주간은 토요일 발행일의 7일 전 토요일부터 전날 금요일까지 실제 Blogger LIVE 일간의 정확한 한영 쌍만 사용합니다. 미공개 초안, 계획된 글, 다른 채널의 글을 섞지 않습니다. 공개 근거가 달라지면 기존 주간 원고·미리보기·승인을 재검토합니다.

## 3. 미리보기와 승인

1. 공식 원문을 확인하고 정확한 한영 원고를 완성합니다. 이미지가 있으면 기존 Google/Blogger 호스트의 실제 URL 맵을 준비하고, 없으면 빈 맵도 명시적으로 준비합니다. placeholder나 Pages 이미지 URL로 준비 완료를 대신하지 않습니다.
2. [Native Preview 절차](BLOGGER_NATIVE_PREVIEW_RUNBOOK.md)에 따라 Blogger DRAFT만 생성·재조회·ID binding합니다. 다른 관리자/자동화가 동시에 편집하지 않는 유효한 단일 작성자 창을 확인해야 합니다. 로컬 잠금이 외부 UI/다른 호스트를 막는다고 주장하지 않습니다.
3. Telegram 원래 대화에 한영 관리자 편집 링크, 원고/이미지 맵 해시, 실제 검증/미검증, 예약 시각을 안내합니다. 비밀 렌더 토큰 URL은 공유하지 않습니다. 관리자 링크는 사용자 기기의 미리보기 접근을 직접 확인했다는 뜻이 아닙니다.
4. 사용자가 해당 버전의 공개를 명시적으로 승인한 뒤 `create_approval_record.py`로 schema v2 기록을 만들고 검증합니다. 주간은 `blogger_weekly_evidence.py`가 생성한 그 회차의 evidence를 `--weekly-evidence`에 결합합니다. natural-language 승인만 있고 파일이 없으면 발행하지 않습니다.
5. 승인 후 원고/이미지의 의미 있는 변경은 새 미리보기·재승인을 거칩니다. 이미 승인된 동일 버전의 내부 준비를 작은 승인 요청으로 반복 분할하지 않습니다. 조기 공개·지연 보충 발행은 원래 시각 승인과 구분합니다.

## 4. Blogger 전용 발행

기존 네 예약의 정시 실행 명령은 아래 Blogger 전용 명령으로 통일합니다. 날짜·시리즈·경로는 실제 회차에서 유도하며 예시 placeholder를 그대로 실행하지 않습니다.

    python3 scripts/blogger_channel_release.py --root <편집원본> --series <시리즈> --date <발행일> --image-urls <정확한이미지맵>

기본은 무쓰기 plan입니다. 당일의 정확한 승인 기록·현 원고/이미지·주간 evidence·원격 상태/충돌·예약 시각을 검사한 뒤, 공개 승인이 있는 같은 회차에만 `--apply`를 사용합니다. 예약 실행 중 새 원고나 승인 기록을 만들어 통과시키지 않습니다. 다른 회차나 전날 글로 대체하지 않습니다.

- Pages `_posts`·GitHub 원격 소스·빌드·sitemap·배포 상태·공개 URL을 읽거나 쓰지 않습니다.
- 기존 동일 LIVE는 변경 없이 확인합니다. 다른 LIVE나 사용자가 수정한 DRAFT를 덮어쓰지 않습니다.
- Preview binding의 정확한 ID·제목·라벨·본문이 다르거나 미해결 저널이 있으면 보류합니다. LIVE/DRAFT/SCHEDULED를 구분하고 모호한 중복은 실패로 처리합니다.
- 모든 외부 쓰기는 계획에 포함된 정확한 글로 제한하고 시도/응답/재조회 결과를 구분해 보존합니다. 한영 외부 요청은 원자적이지 않습니다.
- 타임아웃 등 결과 불확실 시 동일 요청을 맹목 재전송하지 않습니다. 정확한 ID를 전 상태에서 읽어 이미 성공한 부분과 남은 부분을 구분합니다.

공개 성공 저널은 다음 자동작업도 차단하므로 [공개 저널 검증·보관 절차](BLOGGER_PUBLISH_JOURNAL_RUNBOOK.md)를 같은 회차에서 완료합니다. 불확실한 저널은 보존하고 자동 재시도하지 않습니다.

## 5. 완료와 실패 보고

한국어·영어 모두 fresh API에서 LIVE·정확한 본문/라벨이 확인되고, 익명 공개 URL에서 실제 글을 읽을 수 있으며 최종 계획이 변경 없음일 때 해당 쌍을 완료로 봅니다. 이미지가 있으면 실제 Google/Blogger URL의 렌더 가능성도 별도로 확인합니다. 한쪽만 성공하면 성공 ID와 남은 언어·단계를 보존하고 부분 완료로 보고합니다.

스케줄러 `ok`, 승인 파일 생성, 로컬 테스트/CI, 본문 API 저장, 공개 URL 검증, Telegram 전달은 각각 다른 증거입니다. 공개 여부와 메시지 전달 여부를 혼동하지 않습니다. 사용자 기기·브라우저 시각 검수는 직접 확인한 범위만 보고합니다.

## 6. Pages 종료·변경 경계

Blogger 글·이미지·내부 링크·메뉴/표시 metadata가 Pages 호스트에 의존하지 않음을 먼저 확인합니다. 의존성이 있는 기존 글의 대량 수정은 정확한 대상·필드·수량을 제시하고 승인된 범위만 처리합니다. 검증 후 production/Preview Pages의 자동 배포와 공개 서비스를 중단하되 GitHub 저장소·커밋 이력·로컬 초안/승인은 보존합니다. 옛 외부 링크가 남는 것과 현재 Blogger의 런타임 의존을 구분합니다.

기존 양 채널 발행 문서·코드는 역사/복구 참고용입니다. 정기 작업이 이를 호출하거나 Pages 조건을 되살려서는 안 됩니다. 테마·메뉴 재설계, 계정·인증·DNS 변경, 새 유료서비스, 기존 글/백업/저장소 삭제는 이 계약만으로 실행하지 않습니다.
