# AI 한 접시 글로벌화 v.1 — 다국어 구조 설계

## 1. 목표

현재 한국어 블로그를 유지하면서 영어 사이트를 같은 GitHub Pages 프로젝트 안에 추가한다.

- 한국어 기본 주소: `/`
- 영어 기본 주소: `/en/`
- 상단에는 현재 언어의 국기 버튼 하나만 표시한다.
- 버튼을 누르면 언어 선택 드롭다운이 열린다.
- 한국어는 `🇰🇷`, 영어는 `🇺🇸`를 사용한다.
- 국기만으로 의미를 판단하지 않도록 언어명과 접근성 레이블을 함께 제공한다.
- 번역본이 있는 현재 글은 대응하는 번역 글로 이동한다.
- 번역본이 없으면 해당 언어의 홈페이지 또는 시리즈 페이지로 안전하게 이동한다.

## 2. 현재 구조에 대한 결정

현재 프로젝트는 Jekyll 4.3 기반 정적 사이트이며 `site.posts`, Liquid 레이아웃,
GitHub Actions, GitHub Pages로 배포한다. 별도 서버나 데이터베이스는 필요하지 않다.

현재 한국어 URL은 변경하지 않는다. 영어 페이지를 추가하고 기존 한국어 페이지에
영어 대응 링크를 연결하는 additive 방식으로 진행한다.

## 3. URL 규칙

| 대상 | 한국어 | 영어 |
| --- | --- | --- |
| 홈페이지 | `/` | `/en/` |
| 시리즈 | `/series/{slug}/` | `/en/series/{slug}/` |
| 게시글 | `/posts/{slug}.html` | `/en/posts/{slug}.html` |
| 사이트맵 | `/sitemap.xml` | 하나의 sitemap에 양쪽 URL 포함 |

영어 게시글도 기존 게시글의 날짜와 주제에 대응하는 안정적인 slug를 사용한다.
번역이 추가되어도 한국어 canonical URL은 그대로 유지한다.

## 4. 콘텐츠 데이터 모델

기존 게시글 front matter를 깨뜨리지 않고 다음 필드를 추가한다.

```yaml
lang: ko
translation_key: easy-ai-01
series: easy-ai
series_title: 쉽게 먹는 AI
permalink: /posts/2026-09-03-easy-ai-01.html
```

영어 대응 글은 같은 `translation_key`를 사용한다.

```yaml
lang: en
translation_key: easy-ai-01
series: easy-ai
series_title: Easy AI
permalink: /en/posts/2026-09-03-easy-ai-01.html
```

규칙:

- `lang`은 `ko` 또는 `en`으로 통일한다.
- 기존 한국어 글에는 초기 마이그레이션 때 `lang: ko`를 넣는다.
- 같은 주제의 한국어·영어 글은 동일한 `translation_key`를 사용한다.
- 번역되지 않은 글은 한 언어의 글만 존재할 수 있다.
- 시리즈 목록은 현재 페이지의 `lang`과 같은 글만 표시한다.
- 영어 페이지가 없다는 이유로 한국어 글을 영어 목록에 섞지 않는다.

## 5. 시리즈 데이터

기존 `_data/series.yml`의 `slug`는 유지한다. 표시 문구만 언어별로 확장한다.

권장 형태:

```yaml
- slug: easy-ai
  title:
    ko: 쉽게 먹는 AI
    en: Easy AI
  description:
    ko: 뉴스에서 자주 만나는 개념을 일상의 언어로
    en: AI concepts explained in everyday language
```

기존 `title` 문자열을 즉시 제거하지 않고, 구현 단계에서 Liquid 호환성을 확인한 뒤
필요한 범위만 점진적으로 변경한다. 공개 한국어 화면의 문구와 URL은 보존한다.

## 6. 페이지 언어 처리

`site.lang`은 기본값으로 유지하되, 페이지마다 `page.lang`을 우선 적용한다.

```liquid
{% assign current_lang = page.lang | default: site.lang | default: 'ko' %}
<html lang="{% if current_lang == 'en' %}en{% else %}ko-KR{% endif %}">
```

공통 레이아웃의 메뉴·버튼·접근성 문구는 언어별 UI 데이터에서 가져온다.
본문 콘텐츠와 UI 문구를 한 문자열 안에서 JavaScript로 번역하지 않는다.

## 7. 언어 선택 버튼 동작

헤더에는 선택된 언어의 국기 버튼 하나만 표시한다.

```text
현재 한국어: [🇰🇷]
현재 영어:   [🇺🇸]
```

버튼을 클릭하면 다음 목록이 열리는 구조로 구현한다.

```text
🇰🇷 한국어
🇺🇸 English
```

동작 기준:

- `<button>`을 사용하고 `aria-expanded`를 관리한다.
- 드롭다운 바깥 클릭 시 닫힌다.
- `Escape` 키로 닫힌다.
- 키보드 포커스가 드롭다운 안에서 이동 가능해야 한다.
- 모바일에서 헤더·메뉴·다크 모드 버튼과 겹치지 않아야 한다.
- 현재 선택 언어는 목록에서 표시하되, 다시 선택할 수 있게 한다.
- 브라우저 언어 자동 전환은 초기 버전에서 강제하지 않는다.
- 사용자가 고른 언어는 `localStorage`에 저장할 수 있지만 URL이 우선이다.

## 8. 대응 페이지 연결과 fallback

언어 버튼은 먼저 `translation_key`가 같은 대응 페이지를 찾는다.

1. 현재 글의 다른 언어 번역본이 존재하면 그 글로 이동한다.
2. 현재 시리즈의 다른 언어 페이지가 존재하면 그 시리즈로 이동한다.
3. 대응 페이지가 없으면 해당 언어 홈페이지(`/` 또는 `/en/`)로 이동한다.
4. fallback 이동은 조용히 수행하지 않고, 필요한 경우 해당 언어로 안내 문구를 표시한다.

번역되지 않은 글도 한국어 사이트에서 정상적으로 읽을 수 있어야 하며,
영어 사이트의 목록에는 공개된 영어 글만 노출한다.

## 9. SEO 규칙

각 페이지에 다음 정보를 언어에 맞게 출력한다.

- `<html lang>`
- 언어별 `title`
- 언어별 `description`
- 자기 언어 페이지를 가리키는 `canonical`
- 대응 번역본이 있을 때 양쪽을 연결하는 `hreflang`
- `x-default`는 홈페이지처럼 기본 진입 페이지에 한해 검토
- 공개된 영어 페이지만 sitemap에 추가

초안·번역 검토 중인 글은 영어 사이트와 sitemap에 포함하지 않는다.

## 10. 발행 운영 규칙

초기 구현에서는 번역본을 별도 Markdown 게시글로 관리한다.

```text
_posts/2026-09-03-easy-ai-01.md
_posts/2026-09-03-easy-ai-01.en.md  # 사용하지 않음
_posts/2026-09-03-easy-ai-01-en.md  # permalink를 /en/으로 지정
```

Jekyll의 날짜 기반 `_posts` 파일명 규칙과 충돌을 피하기 위해 실제 파일명은
영어 slug를 별도 관리하거나, 영어 콘텐츠를 별도 collection으로 둘 수 있다.
구현 전 소규모 세로 슬라이스에서 Jekyll의 permalink·정렬·`site.posts` 동작을 검증한다.

권장 초기 방식은 기존 `_posts/`를 유지하면서 영어 글도 `_posts/`에 추가하고,
각 글에 명시적인 `lang`, `translation_key`, `permalink`를 부여하는 것이다.
시리즈 아카이브는 반드시 `lang`까지 필터링한다.

## 11. 단계별 공개 범위

초기에는 다음 순서로 영어 콘텐츠를 공개한다.

1. 영어 홈페이지
2. 영어 공통 메뉴·시리즈 소개
3. `쉽게 먹는 AI` 대표 글 2편
4. `오늘 AI 한입` 대표 글 1편
5. 주간 글과 나머지 공개 글
6. 새 글 발행 시 한국어·영어 번역을 별도 승인 후 공개

영어 번역은 자동 생성 초안을 그대로 공개하지 않는다. AI 용어, 공식 출처,
날짜·숫자·이용 조건을 검수한 뒤 공개한다.

## 12. 구현 전 검증 조건

다음 단계에서 최소 세로 슬라이스를 만든다.

- 한국어 홈페이지 ↔ 영어 홈페이지
- 한국어 시리즈 ↔ 영어 시리즈
- 한국어 게시글 ↔ 영어 게시글
- 번역본이 없는 게시글의 fallback
- 언어별 시리즈 목록 분리
- 언어 버튼의 국기 1개 표시와 드롭다운
- 모바일·키보드·Escape·바깥 클릭 동작
- Jekyll 빌드 성공
- 공개 한국어 URL 유지

## 13. 결정하지 않은 항목

다음 항목은 구현 단계에서 실제 Jekyll 빌드로 확인한 뒤 확정한다.

- 영어 콘텐츠를 `_posts/`에 함께 둘지 별도 collection으로 둘지
- 번역되지 않은 글의 안내 문구를 화면에 표시할지
- 브라우저 언어를 최초 방문에만 참고할지
- 영어 홈페이지에서 번역되지 않은 시리즈를 숨길지, 준비 중으로 표시할지

이 결정들은 현재 한국어 운영을 깨뜨리지 않는 범위에서 선택한다.
